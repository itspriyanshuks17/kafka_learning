Kafka CLI

Every script lives in bin/ (or bin\windows\). All of them accept --bootstrap-server host:port to point at the cluster — that flag is the one thing every command below has in common.

4.1 Topic management

# create
bin/kafka-topics.sh --create --topic orders --bootstrap-server localhost:9092 \
  --partitions 6 --replication-factor 3

# list
bin/kafka-topics.sh --list --bootstrap-server localhost:9092

# describe — shows partition leaders, replicas, ISR
bin/kafka-topics.sh --describe --topic orders --bootstrap-server localhost:9092
# Topic: orders  PartitionCount: 6  ReplicationFactor: 3
# Partition: 0  Leader: 1  Replicas: 1,2,3  Isr: 1,2,3
# Partition: 1  Leader: 2  Replicas: 2,3,1  Isr: 2,3,1 ...

# alter partition count (can only increase, never decrease)
bin/kafka-topics.sh --alter --topic orders --partitions 12 --bootstrap-server localhost:9092

# delete
bin/kafka-topics.sh --delete --topic orders --bootstrap-server localhost:9092

4.2 Producing from the CLI

# basic
bin/kafka-console-producer.sh --topic orders --bootstrap-server localhost:9092

# with a key (key:value, tab-separated by default flag below)
bin/kafka-console-producer.sh --topic orders --bootstrap-server localhost:9092 \
  --property "parse.key=true" --property "key.separator=:"
> order-101:{"status":"placed"}

4.3 Consuming from the CLI

# from the beginning of the topic
bin/kafka-console-consumer.sh --topic orders --from-beginning --bootstrap-server localhost:9092

# only new messages (default behavior, no --from-beginning)
bin/kafka-console-consumer.sh --topic orders --bootstrap-server localhost:9092

# show keys too
bin/kafka-console-consumer.sh --topic orders --from-beginning --bootstrap-server localhost:9092 \
  --property print.key=true --property key.separator=" : "

4.4 Consumer group inspection

# list all groups
bin/kafka-consumer-groups.sh --list --bootstrap-server localhost:9092

# describe a group — shows lag per partition (the single most-used ops command)
bin/kafka-consumer-groups.sh --describe --group fraud-detector --bootstrap-server localhost:9092
# GROUP           TOPIC   PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
# fraud-detector  orders  0          10482           10501           19
# fraud-detector  orders  1          9921            9921            0

# reset offsets to earliest for a group (consumers in that group must be stopped first)
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --group fraud-detector \
  --topic orders --reset-offsets --to-earliest --execute

4.5 Broker & cluster info

# cluster metadata (KRaft mode)
bin/kafka-metadata-quorum.sh --bootstrap-server localhost:9092 describe --status

# per-broker config
bin/kafka-configs.sh --bootstrap-server localhost:9092 --entity-type brokers --entity-name 1 --describe

4.6 Common mistakes

  • Running --reset-offsets without --execute — it defaults to a dry run, prints the plan, and changes nothing. Easy to think it worked when it didn't.
  • Forgetting consumers must be stopped (group must have no active members) before resetting offsets — otherwise the command errors out.
  • Using the console producer/consumer for anything beyond quick manual testing — they're debugging tools, not a substitute for a real client (Modules 5–6).

4.7 Summary

Five scripts cover 90% of daily Kafka operations: kafka-topics.sh for topic management, kafka-console-producer/consumer.sh for manual testing, and kafka-consumer-groups.sh for the single most important operational task — watching consumer lag.
