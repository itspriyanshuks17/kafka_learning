20.1 Fundamentals & core concepts

What is Apache Kafka, in one sentence?
A distributed, append-only commit log platform for publishing, storing, and processing streams of events at scale.
Why is Kafka called a "commit log" rather than a message queue?
Because records aren't removed once consumed — they're retained per a policy and can be replayed from any offset, unlike a traditional queue.
What's the single biggest architectural difference between Kafka and RabbitMQ?
RabbitMQ (smart broker, dumb consumer) tracks delivery state itself; Kafka (dumb broker, smart consumer) has each consumer track its own offset.
What is a topic, and is it a physical file?
A topic is a logical named stream of events. It has no single physical file — it's split into partitions, which are the actual physical logs.
What is a partition?
An ordered, immutable, append-only sequence of records — the actual unit of storage, parallelism, and ordering in Kafka.
What is an offset?
A per-partition, monotonically increasing integer marking a record's position within that partition.
Does Kafka guarantee ordering across an entire topic?
No — only within a single partition. Cross-partition ordering isn't guaranteed.
What is a consumer group?
A named set of consumers that split a topic's partitions between them so each partition is read by exactly one consumer in that group at a time.
How does Kafka implement both queue and pub/sub semantics on the same topic?
Multiple consumers in one group behave like a queue (each message processed once); multiple independent consumer groups each get a full copy — pub/sub.
What replaced ZooKeeper in modern Kafka, and why?
KRaft mode — a built-in Raft-based controller quorum — replaced it to remove an external dependency and scale to far more partitions.

20.2 Architecture & internals

What is a broker?
A single Kafka server process that stores partition data and serves producer/consumer requests.
What is a replica, and what's the difference between a leader and a follower replica?
A replica is a copy of a partition on a broker. The leader handles all client reads/writes; followers passively replicate the leader's log and stand by for promotion.
What is the ISR?
The In-Sync Replica set — the leader plus any followers that are fully caught up within a configured lag bound. Only ISR members are eligible for leader election.
Can a follower that's behind on replication become the new leader?
Not while it's out of the ISR — promoting a lagging replica would silently lose acknowledged data, so Kafka only elects from the ISR.
What determines how a producer chooses a partition for a keyed record?
A hash of the key modulo the partition count, computed client-side at send time — the same key always maps to the same partition (until partition count changes).
Why can you increase a topic's partition count but never decrease it?
Partitions are physical ordered logs; removing one would mean discarding or merging its history, breaking ordering and offset semantics — so Kafka disallows it entirely.
What is a segment?
A partition's log is split into segment files, capped by size or age. Only the newest (active) segment accepts writes; older ones are immutable.
How does replication factor relate to fault tolerance?
A replication factor of N tolerates N-1 broker failures without losing that partition's data, assuming enough replicas remain in the ISR.
What does min.insync.replicas control?
The minimum ISR size required for an acks=all write to succeed — it's what turns "replication factor 3" into an actual enforced durability floor.
What happens to producers if the ISR drops below min.insync.replicas?
Producers using acks=all receive errors rather than having writes silently accepted with insufficient durability.

20.3 Producers

What are the three acks settings and their trade-offs?
acks=0 (fastest, can lose data), acks=1 (leader-only ack, can lose data on leader crash before replication), acks=all (waits for full ISR, strongest durability).
What does the idempotent producer guarantee?
Exactly-once delivery per partition per producer session — retries from network issues don't create duplicate records, via a producer ID and per-message sequence numbers.
How do Kafka transactions extend idempotence?
They make a set of writes across multiple partitions/topics atomic — all commit together or all roll back, which idempotence alone (scoped to one partition) can't guarantee.
What's the difference between at-most-once, at-least-once, and exactly-once delivery?
At-most-once may lose messages but never duplicates; at-least-once never loses messages but may duplicate; exactly-once (idempotence + transactions) does neither.
What does linger.ms do?
Deliberately delays sending to let more records accumulate into one batch, trading a small amount of latency for meaningfully higher throughput.
Why would a producer's send() call block?
If buffer.memory fills up faster than records can be sent — often from bursty traffic or an undersized buffer relative to throughput.
What happens if you send a record with no key?
It's distributed round-robin (or sticky-batch) across partitions for load balancing, with no ordering guarantee relative to other records.
Why might increasing partition count later break existing consumer assumptions?
It changes the key-to-partition hash mapping, so a key that used to always land in partition 2 might now land elsewhere, breaking any ordering guarantee consumers relied on.

20.4 Consumers

What's the risk of leaving auto-commit enabled?
The offset can be committed on a timer before processing actually finishes — a crash mid-batch silently skips those records forever.
What triggers a consumer group rebalance?
A consumer joining, leaving, crashing, or being considered dead due to missed heartbeats past session.timeout.ms, or a partition count change.
What is cooperative rebalancing and why does it matter?
Instead of revoking all partitions from all consumers before reassigning ("stop the world"), it only reassigns the partitions that actually need to move — dramatically shortening the processing pause.
What is consumer lag?
The gap between a partition's latest offset and a consumer group's committed offset — the primary signal that a consumer group can't keep up with producer write rate.
Adding more consumers than partitions in a group — what happens?
Extra consumers sit idle; a partition can only be assigned to one consumer per group at a time, so partition count is a hard ceiling on parallelism.
What can cause a consumer to be marked dead even though its process is still running?
Not calling poll() within max.poll.interval.ms — often from slow per-record processing — makes the group coordinator consider it dead and trigger a rebalance.
What's the difference between commitSync() and commitAsync()?
commitSync() blocks until the broker acknowledges the commit; commitAsync() is non-blocking but failures are only surfaced via a callback, not an exception.
How would you replay the last 24 hours of a topic for a given consumer group?
Stop the group's consumers, then use kafka-consumer-groups.sh --reset-offsets --to-datetime with the target timestamp and --execute.

20.5 Reliability & delivery guarantees

How would you design a payment pipeline to never lose an event?
acks=all on the producer, min.insync.replicas ≥ 2, idempotent producer enabled, manual offset commits only after successful processing on the consumer side.
What is a tombstone record?
A record with a key but a null value, used in a compacted topic to mark that key for eventual deletion.
What's the difference between retention and compaction cleanup policies?
Retention deletes whole segments past an age/size threshold regardless of key; compaction keeps only the latest value per key, forever, regardless of age.
Why is Kafka disk-throughput bound rather than IOPS-bound?
Because writes are sequential appends and reads lean heavily on the OS page cache — the workload pattern favors sequential bandwidth over random-access IOPS.
What does the outbox pattern solve?
The "dual write" problem — a crash between updating a database and publishing a Kafka event leaving the two systems inconsistent. Writing the event to an outbox table in the same DB transaction, then streaming it via CDC, closes that gap.
How does Schema Registry prevent breaking changes?
It enforces a compatibility mode (e.g. BACKWARD) and rejects any new schema registration that would violate it before a producer can even use it.
What's the practical difference between BACKWARD and FORWARD schema compatibility?
BACKWARD lets a new schema read old data (safe to upgrade consumers first); FORWARD lets an old schema read new data (safe to upgrade producers first).
How does Kafka Streams achieve exactly-once processing across a read-process-write cycle?
By wrapping the cycle in a Kafka transaction (processing.guarantee=exactly_once_v2) — the input offset commit and the output write commit together or not at all.

20.6 Performance & scaling

Name three producer settings that improve throughput at the cost of latency.
Larger batch.size, higher linger.ms, and enabling compression (lz4/zstd) — all trade a small latency cost for meaningfully higher throughput.
Why might you tune max.poll.records down instead of up?
If per-record processing is slow, a large poll batch risks exceeding max.poll.interval.ms before the batch finishes, triggering an unwanted rebalance.
Is "more partitions" always better for throughput?
No — more partitions means more open file handles, more replication traffic, and slower leader elections; it's a real trade-off, not a free scaling knob.
Why does sizing the JVM heap too large on a broker hurt performance?
It starves the OS page cache Kafka relies on heavily for fast reads — leaving headroom for the page cache usually matters more than a larger heap.
What's the throughput/latency trade-off underlying nearly every tuning knob in Kafka?
Batching, waiting, and buffering all improve throughput by delaying individual records slightly — nearly every performance setting sits on this same dial.
How would you diagnose steadily rising consumer lag?
Check whether consumer count is below partition count (a hard ceiling), then profile per-record processing time rather than assuming it's a CPU or network issue.
What's the risk of setting compression too aggressively (e.g. gzip over lz4/zstd)?
Higher CPU cost per message on both producer and consumer sides, which can become the actual bottleneck on high-throughput topics.
What metric would you alert on to catch broker overload early?
Rising p99 request latency for produce/fetch requests, alongside UnderReplicatedPartitions — both are earlier signals than raw CPU usage.

20.7 Ecosystem

What's the difference between a KStream and a KTable?
A KStream treats every record as an independent event; a KTable keeps only the latest value per key, like a continuously updated table.
What backs a KTable's state internally?
A local state store (RocksDB by default) plus a compacted changelog topic, so state can be rebuilt if an instance restarts or moves.
What's the difference between a source and sink connector in Kafka Connect?
A source connector pulls external data into Kafka; a sink connector pushes Kafka data out to an external system.
Why should Kafka Connect run in distributed mode in production?
Standalone mode is a single process with no fault tolerance — distributed mode coordinates multiple workers via Kafka itself for resilience and scaling.
When would you choose a session window over a tumbling window?
When the natural boundary is a period of inactivity (e.g. a user session) rather than a fixed clock interval — tumbling windows can arbitrarily split one real session.
What problem does ksqlDB solve?
It lets you express stream processing (filters, joins, aggregations) as SQL-like queries instead of writing a Kafka Streams application in Java.
Why would a team choose Protobuf over Avro for Schema Registry?
Usually because they already use Protobuf/gRPC elsewhere in the stack and want one schema format across both systems.
How does Kafka Connect + Debezium implement CDC?
Debezium reads a database's transaction/write-ahead log directly and streams row-level changes into Kafka as events, without querying the tables themselves.

20.8 Security & operations

What are the three independent security layers in Kafka?
SSL/TLS (encryption in transit), SASL (authentication), and ACLs (authorization) — each is configured and enforced separately.
Why is SASL/PLAIN dangerous without SSL?
Credentials are sent essentially in the clear without transport encryption underneath, defeating the purpose of authentication.
What does an ACL actually control?
Whether an authenticated principal is allowed to perform a specific operation (read, write, describe) on a specific resource (topic, group, cluster).
How does IAM authentication in MSK differ from Kafka ACLs?
It ties authorization to standard AWS IAM policies attached to the calling role, instead of managing Kafka-native ACLs as a separate system.
Why does Kafka need multi-AZ broker placement in the cloud?
Replication factor only protects against broker failure if replicas are actually placed on independent failure domains — same-AZ placement defeats that protection during an AZ-level outage.
What's the danger of running out of disk on a broker?
Kafka doesn't degrade gracefully — the broker stops accepting writes entirely, so disk usage needs hard alerting, not just dashboards.

20.9 Scenario-based

Your consumer group's lag is stable at 50,000 but suddenly starts climbing fast. What do you check first?
Whether a consumer instance dropped out of the group (check active member count / recent rebalances) before assuming it's a downstream slowdown or a traffic spike.
A producer using acks=1 reports success, but the message is missing downstream. What's the likely cause?
The leader acknowledged the write but crashed before followers replicated it, and a follower without that record was then elected leader — acks=all with min.insync.replicas would have prevented this.
Two teams need to process the same topic completely independently, at their own pace. How do you set this up?
Put each team's consumers in a separate consumer group — Kafka delivers a full independent copy of the topic to every group.
A new required field with no default was added to an Avro schema, and producer deploys started failing registration. Why?
Adding a required field without a default breaks BACKWARD compatibility — a consumer on the old schema wouldn't know how to fill that field, so the registry rejects it.
You need strict ordering of all events for a given customer, but also want to scale reads horizontally. How?
Key every event by customer ID so all of a customer's events land in the same partition (guaranteeing order), while the topic's overall partition count gives you parallelism across different customers.
A topic was accidentally created with replication factor 1. What's the operational fix?
Use a partition reassignment tool (kafka-reassign-partitions.sh) to add replicas on other brokers — you can increase replication factor for an existing topic without recreating it.
Your consumer's max.poll.interval.ms is being exceeded due to a slow external API call per record. Two fixes?
Lower max.poll.records so each batch finishes faster, or move the slow call off the poll loop into an async worker pool and commit only after it completes.
You need to migrate a topic to more partitions without breaking ordering for existing keys. What's the honest answer?
You can't fully preserve the old key-to-partition mapping when partitions change — the honest fix is planning partition count generously up front, or accepting a brief reordering window during migration.
A Kafka Streams app's state store seems to lose data every time a pod restarts on Kubernetes. Likely misconfiguration?
Missing persistent volume for the RocksDB state directory — without it, the local state store is wiped on restart and has to fully rebuild from the changelog topic, which looks like data loss under load.
How would you safely roll out a breaking schema change that removes a field several consumers still depend on?
Don't remove it directly — deprecate it, keep publishing both old and new fields for a transition window, migrate consumers off the old field, then remove it once nothing depends on it, all governed by the registry's compatibility check at each step.
