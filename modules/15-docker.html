Docker Deployment

Module 3 covered a single Docker broker for a quick test. This module builds a real multi-broker cluster with Docker Compose — the setup most teams actually use for local development and CI.

15.1 Multi-broker Docker Compose

# docker-compose.yml
services:
  kafka1:
    image: apache/kafka:3.9.0
    hostname: kafka1
    ports: ["9092:9092"]
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka1:9092
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka1:9093,2@kafka2:9093,3@kafka3:9093
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
    volumes: ["kafka1-data:/var/lib/kafka/data"]

  kafka2:
    image: apache/kafka:3.9.0
    hostname: kafka2
    ports: ["9093:9092"]
    environment:
      KAFKA_NODE_ID: 2
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka2:9092
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka1:9093,2@kafka2:9093,3@kafka3:9093
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
    volumes: ["kafka2-data:/var/lib/kafka/data"]

  kafka3:
    image: apache/kafka:3.9.0
    hostname: kafka3
    ports: ["9094:9092"]
    environment:
      KAFKA_NODE_ID: 3
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka3:9092
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka1:9093,2@kafka2:9093,3@kafka3:9093
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
    volumes: ["kafka3-data:/var/lib/kafka/data"]

volumes:
  kafka1-data:
  kafka2-data:
  kafka3-data:
docker compose up -d
docker compose exec kafka1 /opt/kafka/bin/kafka-topics.sh \
  --create --topic orders --bootstrap-server kafka1:9092 \
  --partitions 6 --replication-factor 3

15.2 Persistent volumes

The named volumes (kafka1-data, etc.) in the compose file above are what make docker compose down && docker compose up preserve topic data across restarts — without them, every restart wipes the cluster's storage, which is fine for a throwaway test but wrong for anything you're actually developing against over multiple days.

15.3 Adding a UI

  kafka-ui:
    image: provectuslabs/kafka-ui
    ports: ["8080:8080"]
    environment:
      KAFKA_CLUSTERS_0_NAME: local
      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka1:9092,kafka2:9092,kafka3:9092

Gives you topic/partition browsing, consumer group lag, and message inspection in a browser at localhost:8080 — genuinely useful for daily development, not just a nice-to-have.

15.4 Common mistakes

  • Forgetting to set KAFKA_ADVERTISED_LISTENERS to the container's Docker network hostname — clients inside other containers can't resolve localhost the way your host machine can.
  • Not using named volumes — losing all local topic data on every docker compose down.
  • Running all three brokers on a laptop with too little memory allocated to Docker — Kafka brokers are not lightweight processes even at small scale.

15.5 Summary

A three-broker Docker Compose cluster with named volumes gives you a realistic local environment — real replication, real leader election, real rebalancing — without any cloud cost. This is the setup worth reaching for before testing against a shared dev cluster.
