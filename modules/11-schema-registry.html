Schema Registry

Kafka stores bytes, not typed objects — it has no opinion about the shape of your data. Schema Registry is the missing contract layer: it stops a producer's silent field rename from breaking every downstream consumer at 3am.

11.1 The problem it solves

Without a shared contract, a producer team can add, remove, or rename a field, and every downstream consumer finds out only when their deserialization breaks in production. Schema Registry stores versioned schemas centrally and enforces compatibility rules before a new schema is even allowed to register.

11.3 Registering and using an Avro schema

{
  "type": "record",
  "name": "Order",
  "fields": [
    {"name": "orderId", "type": "string"},
    {"name": "amount", "type": "double"},
    {"name": "status", "type": "string", "default": "PLACED"}
  ]
}
props.put("value.serializer", "io.confluent.kafka.serializers.KafkaAvroSerializer");
props.put("schema.registry.url", "http://localhost:8081");
// the serializer automatically registers/validates the schema on first send

11.4 Compatibility modes

ModeRule
BACKWARDNew schema can read data written with the previous schema (safe to upgrade consumers first)
FORWARDPrevious schema can read data written with the new schema (safe to upgrade producers first)
FULLBoth backward and forward compatible — safest, most restrictive
NONENo compatibility checks — any schema change allowed, all safety removed
Practical default — most teams run BACKWARD compatibility: adding a new optional field with a default is safe, but removing a field or changing its type is rejected by the registry before it can break anyone downstream.

11.5 Common mistakes

  • Removing a required field without a default — this breaks BACKWARD compatibility and registration is rejected (which is the registry doing its job, not a bug).
  • Running without Schema Registry at all on a multi-team topic — the "just tell people in Slack" contract works until it doesn't.
  • Choosing NONE compatibility to "move fast" and reintroducing the exact problem Schema Registry exists to prevent.

11.6 Summary

Schema Registry adds a versioned, enforced contract on top of Kafka's raw bytes. Choosing a compatibility mode is choosing which upgrade order (producers-first or consumers-first) your organization can safely support — get this decision right once, and schema changes stop being production incidents.
