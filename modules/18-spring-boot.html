Kafka with Spring Boot

Spring for Apache Kafka wraps the raw Java client (Module 5–6) in annotations and templates so most teams never touch KafkaProducer/KafkaConsumer directly. Underneath, it's the exact same client — every guarantee and trade-off from earlier modules still applies.

18.1 Dependency & configuration

// build.gradle
implementation 'org.springframework.kafka:spring-kafka'
# application.yml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      acks: all
    consumer:
      group-id: fraud-detector
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      auto-offset-reset: earliest
      enable-auto-commit: false

18.2 Producing with KafkaTemplate

@Service
public class OrderProducer {

    private final KafkaTemplate<String, OrderEvent> kafkaTemplate;

    public OrderProducer(KafkaTemplate<String, OrderEvent> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    public void publish(OrderEvent event) {
        kafkaTemplate.send("orders", event.getOrderId(), event)
            .whenComplete((result, ex) -> {
                if (ex != null) log.error("publish failed", ex);
            });
    }
}

18.3 Consuming with @KafkaListener

@Component
public class OrderConsumer {

    @KafkaListener(topics = "orders", groupId = "fraud-detector")
    public void handle(OrderEvent event, Acknowledgment ack) {
        try {
            process(event);
            ack.acknowledge(); // manual commit — mirrors Module 6.3
        } catch (Exception e) {
            // let the error handler / retry mechanism deal with it — see 18.4
            throw e;
        }
    }
}

18.4 Error handling & retry

@Bean
public DefaultErrorHandler errorHandler() {
    var recoverer = new DeadLetterPublishingRecoverer(kafkaTemplate);
    var backOff = new FixedBackOff(1000L, 3L); // retry 3 times, 1s apart
    return new DefaultErrorHandler(recoverer, backOff);
}

After exhausting retries, DeadLetterPublishingRecoverer automatically republishes the failed record to a orders.DLT topic — a standard pattern so a poison-pill message doesn't block the whole partition forever while still preserving it for manual investigation.

18.5 JSON messages & type mapping

spring:
  kafka:
    consumer:
      properties:
        spring.json.trusted.packages: "com.shop.events"
        spring.json.value.default.type: com.shop.events.OrderEvent
Security note — spring.json.trusted.packages: "*" lets the deserializer instantiate arbitrary classes from message content — always scope this to your actual event packages in anything beyond local development.

18.6 Common mistakes

  • Leaving enable-auto-commit at its default true while also manually calling ack.acknowledge() — the two mechanisms conflict; pick one (Module 6.3's logic applies identically here).
  • Not configuring a dead-letter topic — a single malformed message can block an entire partition's consumer indefinitely on retry.
  • Trusting * in spring.json.trusted.packages in production.

18.7 Summary

KafkaTemplate and @KafkaListener are ergonomic wrappers around the exact producer/consumer client from Modules 5–6 — acks, manual offset commits, and delivery guarantees all mean the same thing here. The Spring-specific value-add is declarative retry and dead-letter handling via DefaultErrorHandler.
